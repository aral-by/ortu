# ADR-0008: Session and LLM-loop decisions made in M3

- **Status:** Accepted
- **Date:** 2026-10-20
- **Affects:** systemdesign.md sections 4.4, 5.5, 6.6, 7.2, 8.1, 9, 10.7, 10.8, 12, 13.1, 13.3, 16, 18 and 20; algorithms 01, 03, 06, 09, 12, 15 and 16; `ortu-core`, `ortu-normalize`, `ortu-tr`, `ortu-crypto`, `ortu-stream`, `ortu-py`, `xtask`

## Context

Implementing sessions, the two processing modes, cross-turn assembly, the session map, rehydration, the provenance check and the Python binding (M3) required decisions the design left open. It also showed that written text, which the design treats as a first-class channel, was not detected reliably: values glued to labels and separators (`TC:10000000146`, `0532-123-45-67`, `TR330006100519786457841326`) were missed.

## Decisions

1. **Processing mode is not a session parameter.** `engine.session(call_id, tenant_id)` opens a Realtime session; `Session::push` is Realtime, `Session::finish` is PostCall, and `Engine::redact(&Transcript)` runs PostCall on a whole transcript. Both PostCall entry points share one implementation, so "PostCall output equals batch `redact()`" holds by construction. `finish` consumes the session; dropping it zeroizes the session map and the stored turns. A mode argument would have allowed meaningless combinations (a PostCall session that returns nothing from `push`).
2. **`Engine` lives in `ortu-stream`.** There is no `ortu` facade crate yet; the builder of section 13.1 is `ortu_stream::Engine::builder()`. Detectors, cue rules, weights and policy default to the Turkish set; a key provider is required (section 10.3), and the `encrypt` transform is rejected until the vault exists (M5).
3. **Realtime assembly.** Values assembled across turns are TCKNs, IBANs and phone numbers (`ortu_tr::assemble`). A run opens when a caller turn ends with digits that do not yet form a value and the kind is known: from the assistant's question, otherwise from a cue, most specific kind first (IBAN, TCKN, phone). A turn continues the run only if its first content word starts a number; otherwise the topic changed and the run closes. Assistant backchannels (`evet`, `hı hı`, `devam edin`; a word list in `ortu-normalize`) and an assistant asking again for the kind being dictated keep the run open; any other assistant turn closes it. A voice agent answers every caller turn, so repeating the question while the caller is mid-value is routine. Digits past the kind's length commit a valid prefix. An assembled value scores 1.0 when its validator passes and 0.7 (the partial-match floor of section 7.2) while incomplete. `w_cross` stays reserved for calibration in M7, where it can be fitted instead of guessed.
4. **PostCall grouping.** Caller turns are analyzed as one turn when a number crosses their boundary: the earlier turn ends with digits, the later one starts with digits, only backchannels or questions for an identifier lie between them, and the group spans at most `max_open_turns` caller turns. The analyzer then sees one lattice and every cue of the group. An entity that spans turns has one part per turn, and its token replaces each part, so the persistent transcript never shows a fragment.
5. **Unfinished values are masked in both modes.** Digits (at least two) that follow a cue or a question for a TCKN, IBAN or phone number and do not complete it are masked as `[KIND_INCOMPLETE:...]`, wherever they are in the turn; when they end the turn, Realtime also keeps a run open. The M2 detectors mask partial values only from nine digits on, so without this rule a value the caller never finished (`TC'm on sıfır sıfır sıfır sıfır`, then a new topic) stayed in clear in the persistent transcript. The voice-agent example found this gap.
6. **A bounded, ASCII-only token grammar.** The tolerant matcher accepts up to three spaces or tabs at each gap, ASCII case-insensitive labels, an optional `_INCOMPLETE`/`_INVALID` marker, `:` or `：`, and a digest of 8 or 16 hexadecimal digits. Without brackets, a token must not be glued to a letter, digit or underscore on either side. The bounds make the longest token finite, so the streaming rehydrator can decide exactly which suffix of its buffer may still become a token, and pass the characters around each released piece to the matcher. Unicode case folding is excluded because it would let `K` (Kelvin sign) match `K`.
7. **No constant-time comparison for token lookup.** Section 10.7 asked for `subtle::ConstantTimeEq` on token comparisons. The session map is keyed by label and digest, and digests are not secrets: the LLM holds every token it can present. Timing reveals nothing an attacker does not already have. Two different values under one token make it ambiguous, and resolving an ambiguous token fails instead of guessing.
8. **Read-back defaults.** Names and addresses are read back in full; every other kind, including the kinds the design left "configurable per tenant", is read back partially (`*******0146`). Recall-first applies to read-back too.
9. **The tool boundary.** JSON field names act as cues (`ortu_tr::field_kind`: `tckn`, `phoneNumber`, `ad_soyad`, `Müşteri Adı`). In tool results they apply to every kind, so `{"name": "Ahmet Yılmaz"}` is masked without an introducer; in tool arguments they strengthen identifier kinds only, because a raw name in an argument is not a lookup key into another person's record. JSON numbers are checked like strings. `mask_tool_result` cannot fail and returns the value directly. `register` canonicalizes (digits, E.164, compact IBAN) and always issues a token, so a registered caller ID and the same number spoken later share one token.
10. **Names keep their source spelling.** The value behind a name token is the source text (`Ahmet Yılmaz`); the token is still computed over the folded form, so it does not change. Tools and read-back receive the name as the caller said it.
11. **Audit in M3.** `AuditEvent`, `AuditSink` and `DiscardAuditSink` live in `ortu-core`. The sink adds timestamp and actor, which a crate without clocks or I/O does not know. M3 records tool-boundary decisions (`tool_args_released`, `tool_call_rejected`); masking and reveal events follow with the vault (M5). Releasing arguments fails when the sink fails; a rejection keeps its own reason even if recording it fails.
12. **Written values.** `NormWord::written_value` reads the value inside a written word: a label before the last `:` or `=` is dropped, and a leading `+` and hyphens are removed. Digit-only results join the lattice, so `TC:10000000146`, `+905321234567` and `0532-123-45-67` are read like spoken digits. The IBAN detector also reads IBANs written as one word; a single-word `TR` plus 24 digits that fails its checksum is still masked, as `_INVALID`, because the shape alone is strong evidence. Spans still snap to whole words on every channel; exact sub-word spans for the Text channel stay with the Text defaults in M4.
13. **Python binding.** PyO3 0.30 with the stable ABI (`abi3`, Python 3.9 and newer), built with maturin. Values cross the boundary as JSON-compatible Python objects through Python's own `json` module, so no conversion logic is duplicated. Turns are dicts (`speaker` plus `text` or `words`); `GuardError` carries `reason` and `kind`. PyO3's generated code compiles under the workspace-wide `forbid(unsafe_code)`, so the opt-out section 16 anticipated is not needed. `cargo xtask py` creates `.venv`, installs maturin, builds the extension and runs the Python tests and the example; it is a step of `cargo xtask check`. Tools are run in Python's UTF-8 mode, because maturin fails on Windows when a path contains non-ASCII characters.
14. **`Sayın` introduces a name.** Assistants read names back as `Sayın Ahmet Yılmaz`, and assistant turns are part of the persisted transcript, so the form of address joins the name introducers. Addressees that are not names (`Sayın müşterimiz`, `sayın yetkili`) are in `NOT_NAMES`.
15. **Examples.** The top-level `examples/` holds the Python voice-agent example; it runs in `cargo xtask py`, so it cannot rot. Rust usage is the `ortu-stream` crate documentation, which runs as a doctest. CLI examples follow the CLI in M8.

## Rationale

Decisions 1, 2 and 15 choose the simplest shape that keeps the design's guarantees. Decisions 3, 4 and 9 make the cross-turn and tool-boundary behavior precise enough to test. Decisions 6, 7 and 10 replace a requirement with one that protects the same thing more exactly. Decisions 5, 12 and 14 close gaps found while building M3: an unfinished value, a value written the way people type it, and a name read back by the assistant must not reach a persistent store in clear.

## Consequences

- systemdesign.md, algorithms 01, 06, 12 and 15, the README and CONTRIBUTING describe the implemented behavior.
- Open question 6 (LLM robustness of the token format) moves to M7: the tolerant matcher is in place, and the corruption rate of real LLMs is measured with the evaluation harness rather than estimated.
- The quality gate now needs Python 3.9 or newer on `PATH`.
