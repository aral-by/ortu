# ADR-0006: Detection and scoring decisions made in M2

- **Status:** Accepted
- **Date:** 2026-10-19
- **Affects:** systemdesign.md sections 5.3, 5.4, 7.1-7.3, 8.1-8.3, 10.4, 17 and 18; algorithms 04, 06, 08-11 and 13; `ortu-core`, `ortu-tr`, `ortu-crypto`

## Context

Implementing the core detectors, scoring, conflict resolution, policy and tokens (M2) required decisions the design left open, and showed four places where the design could not be implemented as written.

## Decisions

1. **Word-aligned digit windows.** Numeric detectors read only windows that start and end on word boundaries of the lattice reading. `üç yüz` produces `300`; a window starting at its second digit would claim a value nobody said.
2. **Cue matching on flattened stems, with prefix patterns.** Cue patterns are written in folded Turkish and matched against the flattened stem of each word, so `IBAN'ım`, `ibanım` and `ıban` match `iban`. A trailing `*` makes the last word a prefix (`numara*`, `ulaş*`). Cues add evidence only, so the diacritic collisions that ADR-0004 guards against for number words do not apply.
3. **Small data compiled in, large data as files.** Cue rules, area codes, name introducers and the not-a-name list are small and versioned with the code in `crates/ortu-tr/src/data.rs`, with tests on form and counts. `crates/ortu-tr/data/` arrives in M4 with the gazetteers.
4. **Names without a gazetteer.** M2 detects names after introducers, before honorifics, and in short answers to an assistant's question. `ben X` waits for the gazetteer (M4): without one, `ben belediyeden arıyorum` masks `belediyeden`. A name stops at source punctuation and skips leading fillers; titles (`Müdür Bey`) and finite verbs are never names.
5. **The masking floor is `review_threshold`.** Candidates between the review and mask thresholds are masked and flagged, so they qualify for both labeling and the mask union. The design said `tau_mask`, which would have left review-range candidates unmasked.
6. **Deterministic tie-breaking.** After validation, specificity and score, ties go to the longer span, then the earlier start, so the resolution never depends on detector order.
7. **Score details.** A missing STT confidence contributes 0. A cue from the previous assistant turn is a cue hit at the edge of its window; `w_cross` stays reserved for values assembled across turns (M3). Floors apply after the sigmoid.
8. **`SecretValue` access.** Rust has no friend visibility, so `expose_secret()` is public. Its name keeps every call site searchable for review. `SecretValue` also has no `PartialEq`, to rule out timing-dependent comparisons by accident.
9. **Entities carry `words` and `review`.** Word indices are needed for masking and audio regions; the review flag is the policy decision, recorded with the entity.
10. **Policy file.** A mode presets both thresholds when they are omitted; tokens get a `[tokens]` section; unknown keys and kinds are rejected; credit cards accept only `redact`. `config/ortu.example.toml` and `config/weights.toml` are tested against the compiled-in defaults.
11. **Key providers in M2.** `KeyProvider::token_key` with `StaticKeyProvider` and `EnvKeyProvider`; `data_key` and `FileKeyProvider` arrive with the vault (M5).
12. **Validator test vectors.** IBAN uses the SWIFT IBAN registry example for Turkey. NVİ publishes no TCKN vector set, and phone numbers have no checksum, so TCKN and IBAN vectors were generated by an independent Python implementation of the published algorithms; area codes follow the BTK numbering plan. The M2 acceptance criterion is restated accordingly.

## Rationale

Each decision either removes a false positive class (1, 4), keeps a guarantee the design intended (5, 6, 8), or replaces an unverifiable claim with a precise one (12). Decisions 2, 3, 7, 9, 10 and 11 fill gaps without changing the design's intent.

## Consequences

- systemdesign.md and the affected algorithm documents describe the implemented behavior.
- M4 revisits decisions 3 and 4 when gazetteers arrive; M3 uses `w_cross` and maintains `SessionHints`.
- Changing a cue, area code or name list is a data change in `data.rs`, covered by its tests and the end-to-end cases in `crates/ortu-tr/tests/kinds.rs`.
